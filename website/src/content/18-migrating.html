X x (unix)not supported, use fromUnixSeconds / fromUnixMilliseconds

MMMM MMM MM M, HH H mm m ss s and all the add, isBefore, isToday style functions keep their names.

What will bite you

  • Parsing is strict. Day.js silently picks one reading of ambiguous input. This throws.
  • Cross-field validation. A wrong weekday label throws.
  • No “now” fallback. Missing input doesn’t become the current time.
  • Types matter. format(plainDate, 'HH:mm') throws. Day.js would quietly use 0.
  • It’s Temporal-native, not Date-native. Convert at the boundary.
  • Locales are per call (BCP-47 strings), not global like dayjs.locale('fr').
  • Audit anything leaning on Day.js’s customParseFormat, since that plugin parses leniently.

You can migrate file by file by wrapping both libraries behind one function and dropping the wrapper once nothing uses the old path.
