Parsing

parse() returns a PlainDate, PlainTime, PlainDateTime or ZonedDateTime, depending on which tokens are in the format. In TypeScript you’ll narrow the result with a type guard.

parse('yyyy-MM', '2026-08-04T15:45:30');          // throws: shape mismatch
parse('yyyy-MM-dd', '2026-02-30');                // throws: not a real date
parse('EEEE, yyyy-MM-dd', 'Monday, 2026-08-04');  // throws: it's a Tuesday

Other entry points: safeParse (returns { ok, value | error }), tryParse (value or undefined), parseToParts (matched groups with positions) and compileParser (precompiled, for repeated use).

Rules worth knowing

  • yy follows POSIX strptime: 00–68 is 2000–2068, 69–99 is 1900–1999.
  • hh/h without a throws, and so does mixing HH with hh.
  • HH with a is allowed and cross-checked: '13:05 PM' passes, '01:05 PM' throws.
  • a is case-insensitive. Month and weekday names are case-sensitive.
  • S to SSSSSSSSS go up to nanoseconds. Parse right-pads short input.
  • MMMM/MMM assume a 12-month calendar.

Ambiguity and lenient mode

When a glued numeric run has more than one valid split, parse throws. Zero-pad (MM/dd) or add a separator, or opt in:

parse('yyyy-Md', '2026-121')                              // throws: ambiguous
parse('yyyy-Md', '2026-121', { lenient: true })           // 2026-12-01

The lenient heuristic prefers the split where day ≤ 12, then falls back to the first valid split.

Offsets

Uppercase X/XX/XXX collapse +00:00 to Z. Lowercase never emits Z. On parse, an offset needs a full date and time and a zzz, because an offset is a UTC distance, not a time zone. If both are present they’re cross-checked and a mismatch throws. Range is -12:00 to +14:00, and sub-minute offsets only pass through xxx.
