Locales

Pass a BCP 47 tag as options.locale. The default is 'en-US'.

format(date, 'MMMM d, yyyy', { locale: 'fr-FR' });   // "août 4, 2026"
format(dt, 'h:mm a', { locale: 'ja-JP' });            // "3:45 午後"

Named tokens (MMMM, MMM, EEEE, EEE, a) go through Intl.DateTimeFormat, so non-Gregorian calendars work when the value already carries one: date.withCalendar('hebrew') formats as "Av 21, 5786". Numeric tokens read fields directly and never touch Intl.

Digits

Numeric output is Western digits by default, whatever the locale. Opt in per call:

format(date, 'yyyy-MM-dd', { numberingSystem: 'arab' });   // "٢٠٢٦-٠٨-٠٤"
format(date, 'yyyy-MM-dd', { numberingSystem: 'auto', locale: 'bn-BD' });
parse('yyyy-MM-dd', '٢٠٢٦-٠٨-٠٤', { parseNumberingSystem: 'arab' });

The two options are separate on purpose: you may want localized digits out without expecting them back in. 'auto' uses the locale’s own system and falls back to 'latn' if it isn’t supported. Helpers: convertDigits, convertDigitsToAscii.

Custom vocabulary

Intl misses some cases, a 13-month Hebrew leap year being the usual one. registerLocaleVocab(locale, vocab) takes months, weekdays and day periods. registerLocale(locale, vocab) also takes quarters, eras, ordinals, duration units and relative-time wording. Validation is strict (wrong lengths, empty strings, duplicates, identical AM/PM all throw at registration), and registering clears that locale’s cache. getLocale and hasLocale read it back.
