Format and parse Temporal with the tokens you already know.

yyyy-MM-dd in, string out. Bad input throws instead of quietly handing you garbage. Locale-aware, zero dependencies.

$npm install temporal-fmt
  • 100% coverage (c8)
  • 0 dependencies
  • Node 20+
  • Apache 2.0

Node 26 shipped Temporal without a string formatter. TC39’s position is to use Intl.DateTimeFormat and leave token-style formatting to userland. Fair enough, but if 'yyyy-MM-dd' is muscle memory from date-fns or Day.js, this exists so you don’t have to give that up.

Native on Node 26+. Below that, bring a polyfill or call setTemporal(). Locale-aware tokens need Node 20+ either way, and anything older is untested.

Only want format and parse? temporal-fmt-lite is a frozen snapshot of the 0.8.2 surface: the same two functions and locale support, without recurrence or business calendars. Security and correctness fixes only, no LTS promise. Moving up to the full package later is additive, not a rewrite.
